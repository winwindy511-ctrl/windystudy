# 数字媒体技术2015 · 学习笔记

2026-10-24

## 这本书是什么

《数字媒体技术》（2015）是丁刚毅、王崇文、罗霄等北京理工大学团队编写的数字媒体技术专业入门教材。作者团队常年为奥运会、阅兵这类大型活动做数字表演与仿真，所以这本书不是软件操作手册，而是把「媒体从采集到呈现」的整条技术链讲清楚的工程导论。价值主轴一句话：感知决定参数、参数决定数据量、数据量逼出压缩、压缩与实时性决定应用系统。考试上，数字化表示（采样/量化）、压缩编码（熵编码/运动补偿）、流媒体与版权这三块最容易独立成题。背景：成书于 2015 年——4G 普及、手机人人能拍视频、VR 处在消费前夜，书里压缩、传输占的分量，正是那个年代「内容多了、带宽不够、体验要顺」的写照。

## 一、全书脉络

这本书的主线可以叫「采 → 变 → 改 → 造 → 压 → 传 → 管 → 演」：先把连续世界采进计算机，变成数字，然后改好它，再造出新世界，再把数据压小、传出去、管起来，最后在一个大系统里验收。

开篇先定义对象：什么是数字媒体、它跟传统媒体差在哪（概念章节）。紧接着讲人的感知——眼睛耳朵能分辨到什么程度，这是全书参数的地基（感知基础）。看清楚了，就得把世界搬进计算机：采样、量化、颜色表示，连续的东西变成一串串数字（数字化表示）。数字化好了，素材还不好看，于是逐类处理图像、音频、视频（媒体处理）。处理是改素材，「造出世界」是下一站：图形、动画、游戏、虚拟现实，从「处理别人给的素材」升级到「凭空生成体验」（图形动画游戏VR）。造出来的世界和拍下来的素材都很占地方，于是必须压缩：熵编码去统计冗余、运动补偿去帧间重复（压缩编码）。压小了还得传得动、播得顺，于是有存储、传输和流媒体（存储传输）。内容越来越多，就面临两个新问题：怎么找得到、怎么不被白拿——基于内容的检索和数字水印（内容管理与版权）。最后，所有这些能力要在数字表演与仿真这样的大型系统里同时到位、严格同步，全书在验收中收尾（综合应用）。

## 二、主干梗概

### 数字媒体到底新在哪

手机里一张照片，和墙上贴的海报，都是图，凭什么说数字的就「新」？差别不在清晰度。因为它是 0 和 1 组成的，于是有了三个传统媒体没有的本事：可以无损复制、可以被程序计算和编辑、可以顺着网络分发。**数字媒体**就是以二进制数据形式记录、处理、传输和呈现的媒体内容。例子很好想：一张数字照片可以复制一万次还一模一样；天空的颜色可以被程序一键调蓝；一秒钟就能发给几千公里外的朋友。纸质海报这三样全都做不到。

口诀：「数字媒体 = 能复制、能计算、能分发。」

这一章是给全书装目录，知道各模块在链条上的位置即可，细节不用背。

### 为什么参数要先问人的眼睛和耳朵

手机屏幕刷新率为什么 60Hz 左右就够，而不是越高越好？因为再高，你的眼睛已经分不出来了。人的感知特性决定技术参数的底线：帧率低于临界闪烁频率画面会闪，位深不够会出现色带，音频采样率不够会丢高频。这一块是全书的「宪法」——后面所有的压缩、量化、降采样，能省到什么程度而不被察觉，依据全在这里。例子：电影院里 24 帧/秒的画面看起来是连贯的，因为人眼对快速变化的细节不敏感；这正是「参数够用就好」的证据。

口诀：「人的感知是参数的地基。」

不用记一堆生理数据，记住「参数够用就好，依据在人的眼睛耳朵」就够了。

### 怎么把连续的世界变成数字

唱歌的声音是一条连续起伏的线，计算机只认一串串数字，怎么把线变成数字？答案是两步：采点、分档。**采样**是在时间或空间上按固定间隔取点，把连续的变成离散的一串数；**量化**是把每个点的连续取值归到有限个等级上，用有限位数的数表示，位深越高等级越细；**颜色空间**是用一组坐标描述颜色的数学模型，比如屏幕用的 RGB、印刷用的 CMYK、视频里把亮度与色度分开的 YCbCr。例子：录音每秒取 44100 个点（采样），每个点的高度分 65536 级（量化），声音就进计算机了；拍照取几百万个小方格，每个格子的颜色用 RGB 三个数表示。这两步一旦做了就回不去：采样漏掉点与点之间的信息，量化抹平等级之间的差别——**数字化一定有损**。

口诀：「数字化 = 采样 + 量化，一定有损、不可回头。」

具体用多少采样率、位深不用背，记住「数字化一定有损」这个总账就行。

### 图像、声音、视频各自怎么处理

一张照片太暗、一段录音太噪、一个视频太长，素材拿到手怎么改成能用的内容？三种媒体套路各不相同：图像靠「像素之间有相关性」成片地改——增强、滤波、几何变换、分割与合成；声音是随时间变化的波形，处理就是改波形或改频谱——编辑、混音；视频是带时间轴的图像序列，还多一条音画同步的约束——非线性编辑与特效合成。例子：把照片提亮，是改每个像素的亮度值；把录音里的杂音去掉，是滤掉波形中某个频段；剪辑视频，是在时间轴上挑帧拼接，还要保证嘴型和声音对得上。

口诀：「图像改像素、声音改波形、视频改时间轴。」

这一块是动手环节，记住套路和三种媒体各自的核心差异即可，具体命令不用背。

### 怎么凭空造出一个世界

处理是「改别人给的」，但游戏里的角色、VR 里的博物馆没有人拍给你——怎么凭空造？计算机图形负责把三维场景算成二维图像：**渲染管线**就是把几何、材质、光照一步步算成画面的一整条流水线。动画用**关键帧**：只画首尾两个状态，中间的过渡由程序插值算出来。游戏和**虚拟现实**的难点是实时：每秒要算几十帧，画面还要跟着你的头动，于是「画面要好」和「每秒要算几十帧」互相拉扯。例子：做小球落地的动画，只画它在桌上和落地两个姿势，中间下落过程由软件补齐；戴上 VR 头显转头，画面必须立刻跟着变，慢了就晕。

口诀：「离线追求像，实时追求来得及，VR 两者都要。」

渲染管线的每一步细节先不用深究，记住「造世界 = 建模 + 渲染 + 实时」这个框架就够。

### 为什么数据必须压小

一帧未压缩的高清画面就是几 MB，一秒几十帧就是上百 MB，一部电影几个 TB——不压根本存不下、传不动。先有**码率**这个账本：单位时间的数据量，画质、带宽、存储、算力的交换全用它结算。再有两层方法：**熵编码**按符号出现概率分配长短码字，出现多的用短码，不引入失真，是无损压缩的底子；**运动补偿**利用前后帧的相似性，只编码「这一块从上一帧的哪里移过来」，不重记整帧画面，是视频压缩的核心。例子：拍一个人走过房间，背景几乎没变，运动补偿只记「人从 A 挪到 B」，而不是把整面墙重新记一遍。JPEG、MPEG/H.264、MP3/AAC 这些标准，就是把这些工具组装成流水线。

口诀：「压缩 = 去冗余——熵编码去统计冗余，运动补偿去时间冗余。」

编码标准的细节不用背，记住「压缩靠去冗余、丢的是人察觉不到的部分」。

### 怎么让内容到得快、放得顺

压小了只是「瘦」，但网络带宽会波动，观众又不想等——怎么办？**流媒体**边下载边播放：把媒体切成小段，一边看一边下载，网络好就少缓冲、网络差就多缓冲；码率自适应则要求编码端预先准备多个版本，带宽降了自动换低码率档。例子：手机上看剧，点开几秒就开播，后面的内容边看边下；网速变差时画质自动变糊，但不会卡死。

口诀：「流媒体 = 分段 + 缓冲 + 码率自适应。」

传输协议的具体细节留给问答，记住它解决的是「不想等」和「网络不稳」这两个矛盾。

### 内容多了怎么找、怎么护

上亿张照片和视频，靠人工打标签早就跟不上；而数字内容复制成本几乎为零，又怎么证明「这是谁的」？**基于内容的检索**直接拿图像的颜色、纹理、形状，或音频的旋律特征去查，不用文字标签；**数字水印**把不可见或半可见的标识嵌进媒体数据里，用于溯源和版权认定。例子：上传一张风景照，系统找出风格和颜色相近的其他照片（内容检索）；一张样片被转发多次，仍能从文件里提取出拍摄机构的编号，追到泄露源头（水印）。

口诀：「一个解决找得到，一个解决护得住。」

水印嵌入的具体算法细节留给问答，记住「数字化让复制变便宜，就用技术把稀缺重新造出来」。

### 所有能力最后在哪验收

单看每个文件都合格，但一场大型演出的灯光、音乐、视频、人群要同时对上——怎么证明整套技术链真跑通了？**数字表演与仿真**是在电脑里对大型演出、人群、方阵进行建模、编排与预演：先把舞台、道具、演员建成三维模型，再把人流和队形跑一遍，检查时间、空间、视觉上会不会出问题，最后才去现场排练。例子：大型运动会开幕式前，在电脑里预演几万人的站位、灯光、音乐，检查队形会不会撞、时间对不对得上。它为什么放最后？因为它同时要图形渲染、动画、音频、视频、实时计算、数据管理，任何一环掉链子整个系统就崩。

口诀：「终点不是单个文件，是多元媒体严格同步的系统。」

这一块是全书应用验收，知道「为什么它压轴」即可。

## 三、回环收束

把整条链讲一遍因果：没有采样量化，连续的世界就进不了计算机；数字看不清，图像音频视频的处理就无从下手；处理只能改素材，要凭空造世界才轮到图形动画游戏虚拟现实；造出来的和拍下来的数据太大，逼出压缩；压缩之后要过网络，网络会波动，逼出流媒体；内容规模化，逼出基于内容的检索和数字水印；所有这些能力，最后在数字表演与仿真这类系统里严格同步，才算验收通过。**这台机器缺一环就转不动。**

这本书在跟四种讲法吵架：跟「数字媒体等于软件操作课」吵——原理优先，软件只是出口；跟「媒体各自为政」吵——用一条技术链统一，压缩传输可跨媒体迁移；跟「指标越高越好」吵——够用就好，这直接支撑了压缩的合法性；跟「离线精美与实时可用二选一」吵——VR 和仿真明确站实时。前因后果：成书于 2015 年前后，4G 普及、人人都是内容生产者、VR 消费前夜，产业痛点是「内容多了、带宽不够、体验要顺」；作者团队做大型活动数字表演与仿真，这本书的知识排序，是被他们做过的项目倒推出来的。

核心概念一条线：人的感知特性 → 决定采样率、帧率、位深 → 乘出原始码率 → 太大必须压缩（熵编码 + 运动补偿）→ 压缩数据走网络（流媒体）→ 规模化后要检索（基于内容的检索）与版权（数字水印）→ 最后在数字表演与仿真系统里同步验收。反过来也成立：实时性要求倒逼渲染管线简化、压缩低延迟、编码与传输一起设计。

与其他书对话：跟尼葛洛庞帝《数字化生存》是接着讲——把「从原子到比特」翻译成采样率、位深、码率这些工程参数；跟曼诺维奇《新媒体的语言》是同一件事的两种写法——那边回答「意味着什么」，这边回答「怎么做出来」；跟刘清堂、丁向民《数字媒体技术导论》互补——那边偏媒体类型逐个介绍，这本一条技术链走到底。

论述题答题骨架：先给立场——数字媒体技术的本质，是用计算把人的感知变成可控的数据流，再还原成可感知的体验；然后按链条四层论证——表示层（采样、量化、颜色空间）、处理与生成层（图像音频视频 + 图形动画游戏VR）、约束层（码率、压缩、传输、实时性）、应用层（数字表演与仿真的同步集成）；评价标准——好不好不只看分辨率，要看人的感知是否被满足、系统是否来得及；最后补局限——教材对艺术表达、伦理与隐私讨论较少。

## 如果考试遇到这本书相关的题，这几个点必须踩到

1. **数字化一定有损**：采样漏点、量化抹平，这是后面一切压缩与失真的源头，不能只说「数字化更清晰」。
2. **感知特性是参数依据**：帧率、位深、采样率不是随意定的，是因为人眼人耳的分辨极限在那里，参数够用就好。
3. **压缩的合法性来自感知冗余**：熵编码去统计冗余、运动补偿去时间冗余，丢的是人察觉不到的部分，不叫偷工减料。
4. **码率是贯穿全书的经济学**：画质、带宽、存储、算力四者的交换比，全用码率结算。
5. **实时性是分水岭、集成是终点**：离线渲染追求像、实时系统追求来得及、VR 两者都要；数字表演与仿真 = 多源媒体严格同步的系统，是全书技术链的验收场。
